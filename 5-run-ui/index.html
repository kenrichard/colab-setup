Part 5

Run VERVE's screens on your Mac

This runs the screens from the code on your Mac, using the test site's data. Changes you and Claude make to the screens show up here before anyone else sees them. It takes about ten minutes. Do it straight after Part 4, with the token tab still open.

  1. Start Claude Code in the project

    Open Terminal (⌘ + Space, type Terminal, Return). Copy this, paste it, and press Return:

    cd ~/colab-v2/verve-v2-colab && claude

  2. Ask Claude to set it up

    Copy this and paste it into Claude. Don't press Return yet.

    Set this folder up to run against the test API: create .env.local with VERVE_API_URL=https://api.colab.riworks.app and UI_URL=http://localhost:3003 and VERVE_DEV_TOKEN set to the token at the end of this message, then run npm install. Do not start the server. The token is

    Go back to the Settings tab from Part 4 and click the copy button beside the token again. Click at the end of your message in Claude and paste the token with ⌘ + V. Now press Return.

    Claude asks before writing the file and running commands. Choose Yes. When it says it's done, type /exit and press Return.

  3. Start the screens

    cd ~/colab-v2/verve-v2-colab && npm run dev

    When it says Ready, open localhost:3003. You should already be signed in, with the same organizations as on the test site.

    This is the command to use every time. Leave the Terminal window open while you use the screens. To stop them, click in that window and press Control + C.

  4. Send Ken a screenshot

    Press ⌘ + Shift + 4, then Space, and click the browser window showing localhost:3003.

    If a step stops with an error, send a screenshot of that instead.

How does this work?

VERVE has two parts. The API holds the data and decides who can see what. The screens show it. This runs only the screens on your Mac. They get their data from the test site's API, so you see the same sample data as everyone else, and anything you change there is changed for everyone.

The token stands in for signing in, so the Sign in and Sign out links don't work here. It's saved in a file called .env.local, which never gets uploaded to GitHub.
