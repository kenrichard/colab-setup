Part 5

Run VERVE's screens on your Mac

This runs the screens from the code on your Mac, using the test site's data. Changes you and Claude make to the screens show up here before anyone else sees them. It takes about ten minutes. Do it straight after Part 4, with the token tab still open.

  1. Start a coding session in the screens folder

    In the Claude app, click Code. In the box at the bottom, choose Local, click Select folder, and pick verve-v2-colab inside your colab-v2 folder.

  2. Ask Claude to set it up

    Copy this and paste it into the box. Don't press Return yet.

    Set this folder up to run against the test API: create .env.local with VERVE_API_URL=https://api.colab.riworks.app and UI_URL=http://localhost:3003 and VERVE_DEV_TOKEN set to the token at the end of this message, run npm install, then start the dev server and open it. The token is

    Go back to the Settings tab from Part 4 and click the copy button beside the token again. Click at the end of your message in Claude and paste the token with ⌘ + V. Now press Return.

    Claude asks before writing the file and running commands. Allow it.

  3. Look at the screens

    Claude opens the screens in a browser pane beside the conversation. You can also open localhost:3003 in your usual browser. You should already be signed in, with the same organizations as on the test site.

    Next time, start a coding session in the same folder and ask Claude: Start the dev server and open it. The token is saved, so you don't need it again.

  4. Send Ken a screenshot

    Press ⌘ + Shift + 4, then Space, and click the window showing the screens.

    If a step stops with an error, send a screenshot of that instead.

How does this work?

VERVE has two parts. The API holds the data and decides who can see what. The screens show it. This runs only the screens on your Mac. They get their data from the test site's API, so you see the same sample data as everyone else, and anything you change there is changed for everyone.

The token stands in for signing in, so the Sign in and Sign out links don't work here. It's saved in a file called .env.local, which never gets uploaded to GitHub.
